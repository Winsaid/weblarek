# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Vite

Структура проекта:
- src/ — исходные файлы проекта
- src/components/ — папка с JS компонентами
- src/components/base/ — папка с базовым кодом
- src/components/Models/ — папка с моделями данных
- src/components/Communication/ — папка с классом для связи с сервером
- src/components/View/ — папка с классами представления

Важные файлы:
- index.html — HTML-файл главной страницы
- src/types/index.ts — файл с типами
- src/main.ts — точка входа приложения
- src/scss/styles.scss — корневой файл стилей
- src/utils/constants.ts — файл с константами
- src/utils/utils.ts — файл с утилитами, в том числе `formatPrice(value: number): string` для вывода цены в синапсах

## Установка и запуск
Для работы с сервером создайте в корне проекта файл `.env` со строкой (адрес указывается без слеша в конце):

```
VITE_API_ORIGIN=https://larek.ffapi.ru
```

Для установки и запуска проекта необходимо выполнить команды

```
npm install
npm run dev
```

или

```
yarn
yarn dev
```
## Сборка

```
npm run build
```

или

```
yarn build
```
# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`off(eventName: EventName, callback: Subscriber): void` - снимает обработчик с события.  
`onAll(callback: (event: EmitterEvent) => void): void` - подписка на все события.  
`offAll(): void` - сбрасывает все обработчики.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

Все типы данных описаны в файле `src/types/index.ts`.

#### Тип ApiPostMethods
HTTP-методы, которыми можно отправить данные на сервер.

```ts
type ApiPostMethods = 'POST' | 'PUT' | 'DELETE';
```

#### Интерфейс IApi
Описывает объект для выполнения запросов к серверу. Ему соответствует базовый класс `Api`.

```ts
interface IApi {
  get<T extends object>(uri: string): Promise<T>;
  post<T extends object>(uri: string, data: object, method?: ApiPostMethods): Promise<T>;
}
```

#### Тип TPayment
Способ оплаты заказа: онлайн (`card`) или при получении (`cash`).

```ts
type TPayment = 'card' | 'cash';
```

#### Интерфейс IProduct
Товар магазина. Значение `null` в поле `price` означает, что у товара нет цены и его нельзя купить.

```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

#### Интерфейс IBuyer
Полностью заполненные данные покупателя, необходимые для оформления заказа.

```ts
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

#### Тип TBuyerData
Данные покупателя, которые хранятся в модели в процессе оформления заказа. Отличаются от `IBuyer` тем, что способ оплаты может быть ещё не выбран.

```ts
type TBuyerData = Omit<IBuyer, 'payment'> & {
  payment: TPayment | null;
};
```

#### Тип TBuyerErrors
Результат валидации данных покупателя. Ключ присутствует только у поля с ошибкой, значением является текст ошибки.

```ts
type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;
```

#### Интерфейс IProductsResponse
Ответ сервера на запрос каталога: общее количество товаров и их массив.

```ts
interface IProductsResponse {
  total: number;
  items: IProduct[];
}
```

#### Интерфейс IOrderRequest
Данные заказа, которые отправляются на сервер: данные покупателя, общая стоимость и массив идентификаторов товаров.

```ts
interface IOrderRequest extends IBuyer {
  total: number;
  items: IProduct['id'][];
}
```

#### Интерфейс IOrderResponse
Ответ сервера, подтверждающий оформление заказа: идентификатор заказа и его сумма.

```ts
interface IOrderResponse {
  id: string;
  total: number;
}
```

### Типы данных представлений

Описывают данные, которые презентер передаёт в метод `render` компонентов представления. Все они построены на основе типов выше.

#### Интерфейс ICardActions
Обработчик действия пользователя, который карточка получает в конструкторе. Обработчик создаётся в презентере и генерирует событие через брокер событий.

```ts
interface ICardActions {
  onClick: () => void;
}
```

#### Типы карточек товара
`TCard` - общие для всех карточек данные: название и цена.  
`TCardCatalog` - данные карточки каталога: дополнительно картинка и категория.  
`TCardPreview` - данные карточки подробного просмотра: дополнительно описание, текст кнопки и признак её блокировки.  
`TCardBasket` - данные карточки в корзине: дополнительно порядковый номер.

```ts
type TCard = Pick<IProduct, 'title' | 'price'>;

type TCardCatalog = TCard & Pick<IProduct, 'image' | 'category'>;

type TCardPreview = TCardCatalog & Pick<IProduct, 'description'> & {
  buttonText: string;
  buttonDisabled: boolean;
};

type TCardBasket = TCard & {
  index: number;
};
```

#### Типы компонентов страницы
`IHeader` - счётчик товаров в корзине.  
`IGallery` - массив разметки карточек каталога.  
`IModal` - разметка, которая выводится в модальном окне.  
`IBasket` - разметка товаров корзины, общая стоимость и признак блокировки кнопки оформления.  
`ISuccess` - списанная сумма.

```ts
interface IHeader {
  counter: number;
}

interface IGallery {
  catalog: HTMLElement[];
}

interface IModal {
  content: HTMLElement;
}

interface IBasket {
  items: HTMLElement[];
  total: number;
  buttonDisabled: boolean;
}

interface ISuccess {
  total: number;
}
```

#### Типы форм
`IFormState` - общее для всех форм состояние: валидность и текст ошибок.  
`TOrderForm` - данные формы способа оплаты и адреса.  
`TContactsForm` - данные формы контактов.

```ts
interface IFormState {
  valid: boolean;
  errors: string;
}

type TOrderForm = IFormState & Pick<TBuyerData, 'payment' | 'address'>;

type TContactsForm = IFormState & Pick<TBuyerData, 'email' | 'phone'>;
```

## Модели данных

Модели отвечают только за хранение данных и работу с ними. Они не работают с вёрсткой и не зависят от других классов приложения. При любом изменении данных модель генерирует событие через брокер событий, который получает в конструкторе.

#### Класс Products
Хранит каталог товаров и товар, выбранный для подробного просмотра.

Конструктор:  
`constructor(events: IEvents)` - принимает брокер событий.

Поля класса:  
`items: IProduct[]` - массив всех товаров каталога.  
`selectedItem: IProduct | null` - товар, выбранный для подробного просмотра, или `null`, если товар не выбран.  
`events: IEvents` - брокер событий.

Методы класса:  
`setItems(items: IProduct[]): void` - сохраняет массив товаров и генерирует событие `catalog:changed`.  
`getItems(): IProduct[]` - возвращает массив товаров.  
`getItem(id: string): IProduct | undefined` - возвращает товар по его `id` или `undefined`, если такого товара нет.  
`setSelectedItem(item: IProduct): void` - сохраняет товар для подробного просмотра и генерирует событие `product:selected`.  
`getSelectedItem(): IProduct | null` - возвращает товар для подробного просмотра.

#### Класс Cart
Хранит товары, выбранные покупателем для покупки.

Конструктор:  
`constructor(events: IEvents)` - принимает брокер событий.

Поля класса:  
`items: IProduct[]` - массив товаров в корзине.  
`events: IEvents` - брокер событий.

Методы класса:  
`getItems(): IProduct[]` - возвращает массив товаров в корзине.  
`addItem(item: IProduct): void` - добавляет товар в корзину. Товар, который уже есть в корзине, повторно не добавляется. При добавлении генерирует событие `basket:changed`.  
`removeItem(item: IProduct): void` - удаляет товар из корзины и генерирует событие `basket:changed`.  
`clear(): void` - очищает корзину и генерирует событие `basket:changed`.  
`getTotal(): number` - возвращает стоимость всех товаров в корзине. Товар без цены учитывается как 0.  
`getCount(): number` - возвращает количество товаров в корзине.  
`hasItem(id: string): boolean` - проверяет наличие товара в корзине по его `id`.

#### Класс Buyer
Хранит данные покупателя, которые он указывает при оформлении заказа, и проверяет их.

Конструктор:  
`constructor(events: IEvents)` - принимает брокер событий.

Поля класса:  
`payment: TPayment | null` - способ оплаты или `null`, если он не выбран.  
`email: string` - email покупателя.  
`phone: string` - телефон покупателя.  
`address: string` - адрес доставки.  
`events: IEvents` - брокер событий.

Методы класса:  
`setData(data: Partial<IBuyer>): void` - сохраняет переданные поля. Значения остальных полей не изменяются, поэтому можно сохранить, например, только адрес. Генерирует событие `buyer:changed`.  
`getData(): TBuyerData` - возвращает все данные покупателя.  
`clear(): void` - очищает данные покупателя и генерирует событие `buyer:changed`.  
`validate(): TBuyerErrors` - проверяет, что поля заполнены, и возвращает объект с текстами ошибок. Поле отсутствует в объекте, если ошибки в нём нет. Пустой объект означает, что все данные корректны.

## Слой коммуникации

#### Класс ShopApi
Отвечает за получение данных с сервера и отправку данных на сервер. Выполняет запросы через объект, соответствующий интерфейсу `IApi`, который получает в конструкторе (композиция).

Конструктор:  
`constructor(api: IApi)` - принимает объект для выполнения запросов, например экземпляр класса `Api`.

Поля класса:  
`api: IApi` - объект для выполнения запросов к серверу.

Методы класса:  
`getProducts(): Promise<IProductsResponse>` - выполняет GET запрос на эндпоинт `/product/` и возвращает объект, полученный от сервера, с массивом товаров.  
`createOrder(order: IOrderRequest): Promise<IOrderResponse>` - выполняет POST запрос на эндпоинт `/order/`, передаёт в нём данные заказа и возвращает объект, подтверждающий покупку на определённую сумму.

## Слой представления (View)

Каждый класс представления отвечает за свой блок разметки и наследуется от `Component`. Элементы разметки находятся в конструкторе и сохраняются в полях, слушатели событий устанавливаются один раз в конструкторе. Классы представления не хранят данные и не содержат логики: они только отображают переданные в `render` данные и сообщают о действиях пользователя через брокер событий или через обработчик, полученный в конструкторе.

#### Класс Header
Шапка сайта: кнопка корзины и счётчик товаров в ней. Наследуется от `Component<IHeader>`.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - принимает элемент шапки и брокер событий.

Поля класса:  
`basketButton: HTMLButtonElement` - кнопка открытия корзины.  
`counterElement: HTMLElement` - счётчик товаров в корзине.

Методы класса:  
`set counter(value: number)` - выводит количество товаров в корзине.

По клику на кнопку корзины генерирует событие `basket:open`.

#### Класс Gallery
Каталог товаров на главной странице. Наследуется от `Component<IGallery>`.

Конструктор:  
`constructor(container: HTMLElement)` - принимает элемент каталога.

Методы класса:  
`set catalog(items: HTMLElement[])` - выводит разметку карточек каталога.

#### Класс Modal
Модальное окно. Выводит любую переданную разметку, от него не наследуются другие классы. Наследуется от `Component<IModal>`.

Конструктор:  
`constructor(container: HTMLElement)` - принимает элемент модального окна.

Поля класса:  
`closeButton: HTMLButtonElement` - кнопка закрытия.  
`contentElement: HTMLElement` - элемент для содержимого окна.

Методы класса:  
`set content(value: HTMLElement)` - выводит разметку в окне.  
`open(): void` - показывает окно, добавляя модификатор `modal_active`.  
`close(): void` - скрывает окно, убирая модификатор `modal_active`.

По клику на крестик или вне окна закрывается собственным методом `close()`.

#### Класс Card
Абстрактный родительский класс для трёх карточек товара. Содержит общий для всех карточек функционал: название и цену. Наследуется от `Component<T>`, где `T` расширяет `TCard`.

Конструктор:  
`constructor(container: HTMLElement)` - принимает элемент карточки.

Поля класса:  
`titleElement: HTMLElement` - название товара.  
`priceElement: HTMLElement` - цена товара.

Методы класса:  
`set title(value: string)` - выводит название товара.  
`set price(value: number | null)` - выводит цену в синапсах или «Бесценно», если цены нет.

#### Класс CardWithImage
Абстрактный промежуточный класс для карточек каталога и просмотра, у которых есть картинка и категория. Наследуется от `Card<T>`, где `T` расширяет `TCardCatalog`.

Конструктор:  
`constructor(container: HTMLElement)` - принимает элемент карточки.

Поля класса:  
`imageElement: HTMLImageElement` - картинка товара.  
`categoryElement: HTMLElement` - категория товара.

Методы класса:  
`set title(value: string)` - выводит название товара и использует его как альтернативный текст картинки.  
`set image(value: string)` - выводит картинку товара по полному адресу.  
`set category(value: string)` - выводит категорию и устанавливает модификатор фона из `categoryMap`.

#### Класс CardCatalog
Карточка товара в каталоге (шаблон `#card-catalog`). Наследуется от `CardWithImage<TCardCatalog>`.

Конструктор:  
`constructor(container: HTMLElement, actions: ICardActions)` - принимает элемент карточки и обработчик клика по карточке.

По клику на карточку вызывает обработчик `actions.onClick`, который генерирует событие `card:select`.

#### Класс CardPreview
Карточка подробного просмотра товара (шаблон `#card-preview`). Наследуется от `CardWithImage<TCardPreview>`.

Конструктор:  
`constructor(container: HTMLElement, actions: ICardActions)` - принимает элемент карточки и обработчик клика по кнопке.

Поля класса:  
`descriptionElement: HTMLElement` - описание товара.  
`buttonElement: HTMLButtonElement` - кнопка покупки или удаления товара из корзины.

Методы класса:  
`set description(value: string)` - выводит описание товара.  
`set buttonText(value: string)` - выводит текст кнопки.  
`set buttonDisabled(value: boolean)` - блокирует или разблокирует кнопку.

По клику на кнопку вызывает обработчик `actions.onClick`, который генерирует событие `card:toggle`.

#### Класс CardBasket
Карточка товара в корзине (шаблон `#card-basket`). Наследуется от `Card<TCardBasket>`.

Конструктор:  
`constructor(container: HTMLElement, actions: ICardActions)` - принимает элемент карточки и обработчик клика по кнопке удаления.

Поля класса:  
`indexElement: HTMLElement` - порядковый номер товара.  
`deleteButton: HTMLButtonElement` - кнопка удаления товара.

Методы класса:  
`set index(value: number)` - выводит порядковый номер товара.

По клику на кнопку удаления вызывает обработчик `actions.onClick`, который генерирует событие `basket:remove`.

#### Класс Basket
Корзина (шаблон `#basket`). Наследуется от `Component<IBasket>`.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - принимает элемент корзины и брокер событий.

Поля класса:  
`listElement: HTMLElement` - список товаров.  
`totalElement: HTMLElement` - общая стоимость.  
`checkoutButton: HTMLButtonElement` - кнопка оформления заказа.

Методы класса:  
`set items(items: HTMLElement[])` - выводит разметку карточек товаров. Если массив пустой, список очищается, и стили стартового набора показывают в нём надпись «Корзина пуста».  
`set total(value: number)` - выводит общую стоимость.

#### Класс Form
Абстрактный родительский класс для двух форм оформления заказа. Содержит общий для форм функционал: кнопку отправки, вывод ошибок, обработку ввода и отправки. Наследуется от `Component<T>`, где `T` расширяет `IFormState`.

Методы класса:  
`set valid(value: boolean)` - разблокирует кнопку отправки, если форма валидна.

При вводе в поле генерирует событие `form:change` с объектом `{ [имя поля]: значение }`. При отправке формы генерирует событие `<имя формы>:submit`, то есть `order:submit` или `contacts:submit`.

## События

#### События моделей данных
| Событие | Где генерируется | Описание |
|---|---|---|
| `catalog:changed` | `Products.setItems` | Изменился каталог товаров |
| `product:selected` | `Products.setSelectedItem` | Изменился товар, выбранный для просмотра |
| `basket:changed` | `Cart.addItem`, `Cart.removeItem`, `Cart.clear` | Изменилось содержимое корзины |
| `buyer:changed` | `Buyer.setData`, `Buyer.clear` | Изменились данные покупателя |

#### События представлений
| Событие | Где генерируется | Данные | Описание |
|---|---|---|---|
| `card:select` | `CardCatalog` | `IProduct` | Выбрана карточка для просмотра |
| `card:toggle` | `CardPreview` | - | Нажата кнопка «Купить» или «Удалить из корзины» в карточке просмотра |
| `basket:remove` | `CardBasket` | `IProduct` | Нажата кнопка удаления товара из корзины |
| `basket:open` | `Header` | - | Нажата кнопка открытия корзины |
| `order:open` | `Basket` | - | Нажата кнопка «Оформить» |
| `form:change` | `Form`, `OrderForm` | `Partial<IBuyer>` | Изменились данные в форме |
| `order:submit` | `Form` (форма `order`) | - | Нажата кнопка «Далее» |
| `contacts:submit` | `Form` (форма `contacts`) | - | Нажата кнопка «Оплатить» |
| `success:close` | `Success` | - | Нажата кнопка закрытия сообщения об успешном заказе |

## Презентер

Презентер реализован в основном скрипте приложения `src/main.ts`, отдельного класса для него нет. Так как у приложения одна страница, достаточно одного презентера.

При запуске презентер создаёт брокер событий, модели данных, класс `ShopApi` и компоненты представления, затем приводит модели корзины и покупателя в стартовое состояние методами `clear()`, чтобы корзина, счётчик и формы отрисовались по событиям моделей. После этого презентер запрашивает с сервера каталог, добавляет `CDN_URL` к адресу картинки каждого товара и сохраняет товары в модель `Products`. Дальше код презентера состоит из обработчиков событий. Презентер не генерирует события: события генерируют модели и представления, а презентер их обрабатывает. Обработчики, которые презентер передаёт в конструкторы карточек, только генерируют событие через брокер.

Представления перерисовываются только при обработке события модели об изменении данных. При открытии корзины и форм в модальное окно передаётся их уже готовая разметка: `basket.render()`, `orderForm.render()`, `contactsForm.render()`.

Обработка событий моделей:
- `catalog:changed` - создаёт карточки `CardCatalog` для всех товаров и выводит их в `Gallery`.
- `product:selected` - выводит выбранный товар в `CardPreview` и открывает его в модальном окне. Текст и блокировку кнопки определяет презентер: «Недоступно», если у товара нет цены, «Удалить из корзины», если товар уже в корзине, иначе «Купить».
- `basket:changed` - обновляет счётчик в `Header` и содержимое `Basket`.
- `buyer:changed` - выводит данные покупателя и ошибки валидации в `OrderForm` и `ContactsForm`.

Обработка событий представлений:
- `card:select` - сохраняет товар в модели как выбранный для просмотра.
- `card:toggle` - добавляет выбранный товар в корзину или удаляет его из корзины и закрывает модальное окно.
- `basket:open` - открывает готовую разметку корзины в модальном окне.
- `basket:remove` - удаляет товар из корзины.
- `order:open` - открывает готовую форму способа оплаты и адреса.
- `form:change` - сохраняет данные из формы в модели покупателя.
- `order:submit` - открывает готовую форму контактов.
- `contacts:submit` - собирает заказ из данных покупателя и корзины, отправляет его на сервер, после ответа очищает корзину и данные покупателя и показывает сообщение об успешной оплате.
- `success:close` - закрывает модальное окно.
